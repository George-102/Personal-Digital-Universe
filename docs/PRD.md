# Personal Digital Universe
# 3D Immersive Personal Portfolio — 产品需求文档

**项目名称：** Personal Digital Universe

**项目类型：** 3D 沉浸式个人介绍网站（Personal Portfolio / About Me）

**产品定位：** 一个融合 3D 空间交互、动态视觉特效、个人经历展示、科研成果、开源项目、软件产品及文学创作的沉浸式个人数字空间。

**设计关键词：** 3D、Immersive、Futuristic、Interactive、Cinematic、Minimalist、Dynamic。

**核心理念：** 不仅仅是展示个人信息，而是通过一个具有空间感、探索感和故事性的数字世界，让访客认识网站所有者。

---

# 一、项目背景与目标

## 1.1 项目背景

本项目旨在创建一个具有鲜明个人风格的 3D About Me 网站，用于展示个人身份、学习经历、科研探索、开源项目、独立软件产品、文学创作以及跨领域兴趣。

网站所有者是一名计算机科学专业本科大三学生，目前主要处于研究生考试准备、实习准备和科研探索阶段，同时积极参与开源社区和软件产品开发。

个人身份包括：

1. Computer Science Student：计算机科学专业学生。
2. Researcher：从事 Dynamic Airspace Configuration（DAC）、Large Language Models（LLM）和 Multi-Agent Reinforcement Learning（MARL）相关研究。
3. Open Source Developer：积极参与 GitHub 开源项目。
4. Software Developer：具有独立软件开发和产品发布经历。
5. Writer：创作《法渊》等玄幻文学作品。
6. Lifelong Learner：热衷于阅读、学习和探索不同领域的知识。

网站需要体现上述多元身份，同时突出技术研究、创造力和个人探索精神。

## 1.2 产品目标

- 建立一个具有高度辨识度的个人数字品牌。
- 通过 3D 场景和动态特效创造独特的视觉体验。
- 全面展示个人教育背景、专业技能和成长经历。
- 展示科研项目、学术成果和研究方向。
- 展示 GitHub 开源项目和已经发布的软件产品。
- 展示个人文学作品、文章、阅读和思想。
- 提供专业的个人联系方式，促进科研、技术和商业合作。
- 为未来的研究成果、软件产品和个人经历提供持续扩展能力。

## 1.3 核心产品原则

### 视觉体验优先，但不能牺牲信息传达

3D 和动态效果是网站的重要特色，但不能让访客为了浏览内容而进行复杂操作。

### 空间化展示

不同内容模块应拥有相对独立的视觉空间，构成一个统一的个人数字宇宙。

### 交互驱动探索

访客不只是被动阅读信息，还可以通过鼠标、滚动、点击和触摸探索网站。

### 内容真实性

所有个人经历、论文、技术能力和项目成果都应基于真实信息。

### 性能优先

复杂 3D 场景应具有合理的资源管理策略，保证网站在普通电脑和移动设备上仍然能够正常使用。

# 二、用户角色

## 2.1 普通访客（Visitor）

可以浏览网站所有公开信息，通过交互探索个人数字空间。

## 2.2 潜在招聘人员或学术导师（Recruiter / Academic Advisor）

希望了解个人教育背景、专业能力、科研成果和项目经验。

## 2.3 潜在合作伙伴（Potential Collaborator）

希望了解个人科研方向、技术能力及软件产品，从而寻找合作机会。

## 2.4 技术开发者（Developer）

希望了解个人开源项目、技术实践和软件开发经验。

## 2.5 文学爱好者（Literature Enthusiast）

希望了解个人文学作品、创作理念以及阅读和思想记录。

## 2.6 网站所有者（Owner）

负责维护个人信息、项目、研究成果、文章和其他展示内容。

# 三、用户故事（User Stories）

# 模块一：3D 首页与沉浸式入口（3D Hero Experience）

## US-001：访客进入个人数字空间

**概述：**

作为一名首次访问网站的游客，我希望进入网站时能够获得具有沉浸感和视觉冲击力的 3D 体验，以便快速了解网站所有者的个人定位，并产生继续探索的兴趣。

**详述：**

1. 网站首页采用全屏 3D Hero Section 设计。
2. 首页应以深色科技风格为主要视觉基调。
3. 核心场景可以由以下元素构成：
   - 三维空间网格（3D Grid）。
   - 动态粒子系统（Particle System）。
   - 悬浮几何体（Floating Geometries）。
   - 动态光照和体积感光效。
   - 具有深度感的空间背景。
   - 抽象的数字轨道、节点和连接线。
4. 场景中心突出展示个人姓名或个人英文名称。
5. 姓名附近展示具有个人特色的身份描述：

   "Computer Scientist · Researcher · Developer · Writer · Explorer"

6. 展示个人当前状态，例如：

   "Building, Researching, Creating."

7. 页面应当具有明确的探索入口，例如 Explore My Universe。
8. 首页可以设计一个具有空间感的 3D 核心物体，作为整个网站的视觉中心。
9. 访客进入首页后，应当能够直观理解页面可以通过滚动继续探索。
10. 3D 场景不能遮挡个人姓名和重要文字。

**验收标准：**

- 正常场景：访客打开网站后，可以看到完整的 3D 首页场景、个人姓名及身份介绍。
- 正常场景：3D 场景中的几何体、粒子和光效具有持续但不过度的动态效果。
- 正常场景：访客可以点击 Explore 进入后续内容。
- 正常场景：页面能够适应不同分辨率的屏幕。
- 异常场景：WebGL 不可用时，首页自动显示静态背景或轻量 CSS 动态背景，核心内容依然可见。
- 异常场景：3D 资源加载失败时，不得导致首页白屏或文字无法显示。

## US-002：访客与 3D 场景进行交互

**概述：**

作为一名网站访客，我希望能够通过鼠标或触摸与 3D 场景进行交互，以便获得更强的参与感和空间探索体验。

**详述：**

1. 鼠标移动时，3D 场景中的相机或核心物体可以产生轻微的视差变化。
2. 鼠标移动时，粒子和部分空间元素可以产生跟随或排斥效果。
3. 鼠标悬停在指定的 3D 物体上时，物体应出现动态反馈，例如：
   - 高亮发光。
   - 轻微放大。
   - 旋转速度变化。
   - 显示辅助文字。
4. 允许访客通过拖动操作旋转指定的 3D 物体。
5. 可以为重要交互物体添加点击事件。
6. 点击交互物体时，可以触发页面跳转或进入对应内容区域。
7. 不应强制访客操作 3D 场景才能访问页面内容。
8. 鼠标视差应当具有平滑的惯性效果，避免突兀移动。

**验收标准：**

- 正常场景：移动鼠标时，场景能够产生相应的空间反馈。
- 正常场景：悬停指定物体时，物体能够出现明显但克制的交互反馈。
- 正常场景：点击指定物体时，可以执行正确的跳转行为。
- 异常场景：用户快速移动鼠标时，不应出现明显的画面抖动。
- 异常场景：触摸设备不支持鼠标悬停时，仍能通过点击完成对应操作。

## US-003：访客体验电影级页面转场

**概述：**

作为一名网站访客，我希望在浏览不同模块时体验具有电影感和空间感的动态转场，以便让整个网站更像一个连续的数字世界，而不是简单拼接的网页。

**详述：**

1. 网站各内容模块可以通过滚动触发 3D 场景变化。
2. 当访客从首页进入下一个模块时，可以实现：
   - 相机缓慢推进或后退。
   - 场景背景渐变。
   - 3D 物体移动或旋转。
   - 粒子向新的场景聚集或扩散。
   - 内容面板从空间中展开。
3. 相邻模块之间应当拥有连续的视觉叙事。
4. 允许使用滚动驱动动画（Scroll-driven Animation）。
5. 页面滚动应保持正常浏览器行为，不应强制劫持滚轮。
6. 转场动画不能导致访客无法立即阅读已经进入视口的内容。
7. 访客快速滚动时，动画应当能够正确中断、衔接或完成，不出现多个相互冲突的动画状态。

**验收标准：**

- 正常场景：访客滚动页面时，指定场景能够触发对应的空间转场。
- 正常场景：动画结束后，目标内容模块能够清晰呈现。
- 正常场景：快速上下滚动不会造成动画状态混乱。
- 异常场景：动画执行失败时，内容仍然可以正常访问。
- 异常场景：用户开启减少动态效果时，自动使用简化转场。

# 模块二：全局导航与页面交互（Navigation & Interaction）

## US-004：访客使用空间化导航系统

**概述：**

作为一名访客，我希望通过直观的导航系统快速访问不同内容模块，以便在沉浸式 3D 网站中仍然能够高效获取信息。

**详述：**

1. 网站设置全局导航栏。
2. 导航项目包括：
   - Home
   - About
   - Journey
   - Research
   - Projects
   - Writing
   - Interests
   - Contact
3. 导航栏可以采用透明玻璃质感（Glassmorphism）。
4. 支持固定在页面顶部。
5. 当前所在模块应当具有明显的激活状态。
6. 点击导航项目后，页面平滑移动到对应区域。
7. 导航切换可以配合 3D 相机运动或局部空间过渡。
8. 移动端采用折叠菜单。
9. 导航必须清晰易用，不能为了视觉效果隐藏核心入口。

**验收标准：**

- 正常场景：点击导航项目后，可以准确到达对应模块。
- 正常场景：页面滚动时，导航激活状态同步变化。
- 正常场景：导航栏在不同背景下始终具有足够的可读性。
- 异常场景：目标模块不存在时，不应产生无效跳转。
- 异常场景：移动端可以通过触摸正常展开和关闭导航。

## US-005：访客获得动态滚动反馈

**概述：**

作为一名访客，我希望在滚动页面时获得连续的视觉反馈，以便清晰感知浏览进度和当前所在位置。

**详述：**

1. 设置页面滚动进度指示器。
2. 可以使用细线、光点或轨道展示整体浏览进度。
3. 页面滚动时，背景场景可以产生轻微变化。
4. 当前内容模块可以通过文字、光效或其他标识突出。
5. 不同模块可以具有独立的动态背景状态。
6. 滚动效果不得影响正常页面操作。

**验收标准：**

- 正常场景：页面滚动时，进度指示器能够同步更新。
- 正常场景：进入不同模块时，视觉状态能够正确切换。
- 异常场景：快速滚动时，进度指示器不会出现明显延迟或错位。

# 模块三：个人介绍与技能（About & Expertise）

## US-006：访客查看个人介绍

**概述：**

作为一名首次访问网站的游客，我希望了解网站所有者的个人背景、身份定位和发展方向，以便建立完整的个人认知。

**详述：**

1. 设置独立的 About Me 区域。
2. 展示个人姓名、个人照片或具有代表性的 3D 形象。
3. 展示个人自我介绍。
4. 个人介绍应包括：
   - 计算机科学专业本科大三学生。
   - 目前准备研究生考试及实习。
   - 从事 LLM、MARL 与动态空域配置相关研究。
   - 参与 GitHub 开源项目。
   - 独立开发并发布软件产品。
   - 创作《法渊》等玄幻文学作品。
   - 对阅读、数学、哲学、经济学和其他领域保持兴趣。
5. 可以利用 3D 人物形象、抽象头像或几何元素增强视觉表现。
6. 提供 Download CV 入口。
7. 个人介绍应当具有一定的叙事性，而不是简单罗列信息。

**验收标准：**

- 正常场景：访客可以阅读完整的个人介绍。
- 正常场景：个人形象和文字信息能够清晰呈现。
- 正常场景：点击 Download CV 可以下载已配置的简历。
- 异常场景：头像或 3D 模型加载失败时，文字内容仍可正常显示。
- 异常场景：未配置简历时，不显示无效下载入口。

## US-007：访客浏览个人技术能力

**概述：**

作为一名招聘人员或潜在合作伙伴，我希望了解网站所有者的技术能力和专业领域，以便判断其技术背景和专业水平。

**详述：**

1. 设置 Skills & Expertise 区域。
2. 技能按照领域分类：
   - Computer Science。
   - Software Engineering。
   - Full-Stack Development。
   - Artificial Intelligence。
   - Research & Scientific Computing。
   - Tools & Technologies。
3. 展示实际掌握的编程语言、框架、算法和工具。
4. 可以采用空间化技能展示方式，例如：
   - 3D 技能星图。
   - 动态技术标签。
   - 悬浮分类卡片。
   - 技术领域之间的关联网络。
5. 鼠标悬停技能节点时，可以显示技能名称和相关描述。
6. 点击技能节点时，可以查看关联项目或研究。
7. 不应使用缺乏客观依据的熟练度百分比。

**验收标准：**

- 正常场景：访客可以查看不同领域的技能分类。
- 正常场景：悬停或点击技能节点时，可以查看对应信息。
- 异常场景：未配置关联项目时，技能仍能够正常展示。

# 模块四：个人经历（Journey & Experience）

## US-008：访客探索个人成长时间线

**概述：**

作为一名访客，我希望通过具有交互性的时间线了解网站所有者的重要经历，以便理解其成长轨迹和个人发展过程。

**详述：**

1. 设置 Journey / Experience 区域。
2. 时间线可以采用 3D 空间轨道或具有深度感的节点网络。
3. 不同时间节点代表重要个人经历。
4. 经历包括：
   - 教育经历。
   - 科研项目。
   - 开源项目。
   - 软件产品发布。
   - 竞赛经历。
   - 实习与工作经历。
   - 文学创作。
5. 每个节点包含时间、标题、简介、分类和详细信息入口。
6. 鼠标悬停节点时显示摘要信息。
7. 点击节点时，可以展开详细内容面板。
8. 可以通过时间轴位置表达不同经历的时间顺序。
9. 不应将时间线设计为必须旋转 3D 场景才能阅读的形式。

**验收标准：**

- 正常场景：访客可以查看完整的个人经历。
- 正常场景：鼠标悬停时间节点时，可以看到相关摘要。
- 正常场景：点击时间节点可以查看对应详情。
- 正常场景：时间线在移动端能够转换为适合触摸操作的布局。
- 异常场景：没有详细信息的节点仍然可以展示基本内容。

## US-009：访客查看教育背景

**概述：**

作为一名学术导师或招聘人员，我希望了解网站所有者的教育背景，以便了解其专业基础和学术经历。

**详述：**

1. 展示学校、学院、专业及学历阶段。
2. 展示入学和预计毕业时间。
3. 可以展示重要课程、学习经历和学术兴趣。
4. 通过简洁的信息卡片或时间节点呈现教育经历。
5. 正在准备研究生考试应作为当前状态展示，不应视为已经获得研究生学历。

**验收标准：**

- 正常场景：访客可以完整查看教育背景。
- 异常场景：信息未配置时，不显示空字段。
- 异常场景：未获得的学历不能被展示为已完成学历。

# 模块五：科研与学术研究（Research & Science）

## US-010：访客探索科研方向

**概述：**

作为一名科研人员或潜在合作伙伴，我希望了解网站所有者的科研方向和研究内容，以便判断是否存在学术交流或研究合作的可能性。

**详述：**

1. 设置 Research 区域。
2. 该区域应体现专业、理性和未来科技感。
3. 重点展示 Dynamic Airspace Configuration（DAC）相关研究。
4. 主要研究领域包括：
   - Dynamic Airspace Configuration。
   - Dynamic Airspace Sectorization。
   - Large Language Models。
   - Multi-Agent Reinforcement Learning。
   - Agentic AI。
   - AI for Air Traffic Management。
5. 重点展示 LLM 与 MARL 结合的科研探索。
6. 介绍动态空域配置面临的问题：
   - 动态交通需求。
   - 空域结构重构。
   - 空域容量与安全性。
   - 管制员工作负载均衡。
   - 动态决策和协同优化。
7. 展示研究使用的算法、仿真平台、数据和关键技术。
8. 可以通过 3D 空域模型、空间网格、动态扇区、飞行轨迹等视觉元素展示研究背景。
9. 3D 科研可视化如果没有真实数据支撑，应明确作为概念性示意图，而不是声称代表真实仿真结果。
10. 每个研究方向可以进入独立详情页面。

**验收标准：**

- 正常场景：访客能够清晰了解研究方向和核心问题。
- 正常场景：访客可以查看研究项目详情。
- 正常场景：3D 空域示意图能够正常加载和交互。
- 异常场景：3D 可视化加载失败时，文字介绍仍然可见。

# 模块十一：多设备适配（Responsive Experience）

## US-021：访客在不同设备上体验网站

**概述：**

作为一名使用不同设备访问网站的访客，我希望网站根据设备性能和屏幕尺寸自适应调整 3D 场景与布局，以便在不同设备上获得良好的体验。

**详述：**

1. 支持 Desktop、Laptop、Tablet 和 Mobile。
2. 桌面端：
   - 完整 3D 场景。
   - 丰富的鼠标交互。
   - 多层次视差效果。
   - 完整的动态背景。
3. 平板端：
   - 适当简化 3D 场景。
   - 保留主要交互效果。
   - 调整卡片和布局。
4. 移动端：
   - 降低粒子数量。
   - 简化复杂 3D 模型。
   - 减少高成本光照和后处理效果。
   - 使用触摸交互。
   - 必要时使用静态或 CSS 动态背景替代复杂场景。
5. 设备性能不足时，允许自动降低渲染质量。
6. 移动端不能仅仅是桌面端的简单缩放版本。

- 正常场景：网站能够在主流移动浏览器中正常运行。
- 正常场景：移动端布局不出现横向溢出。
- 正常场景：低性能设备可以使用简化渲染模式。
- 异常场景：设备不支持 WebGL 时，自动使用降级视觉方案。

5. 保留必要的导航、按钮和交互反馈。
6. 禁止使用高频闪烁和强烈刺激视觉的动态效果。

**验收标准：**

- 正常场景：开启减少动态效果后，复杂滚动动画和非必要 3D 动画被关闭或简化。
- 正常场景：简化模式下，所有核心内容和导航功能仍然可用。
- 异常场景：浏览器未提供相关系统设置时，使用默认动画模式。

# 五、3D 与动态视觉设计规范（3D & Motion Design）

本章节是本项目的核心设计要求。

## 5.1 整体视觉方向

采用 Futuristic Digital Universe 风格。

关键词：

- Futuristic。
- Cyber Space。
- Digital Universe。
- Cinematic Lighting。
- Spatial UI。
- Glassmorphism。
- Abstract Geometry。
- Particle Simulation。
- Holographic Interface。

整体建议采用深色背景、蓝紫色光效、青色强调色，以及适度的空间景深。

## 5.2 3D 场景设计

### 场景一：数字宇宙（Hero Scene）

作为整个网站的视觉中心。

场景元素：

- 动态粒子。
- 环绕轨道。
- 空间网格。
- 动态光照。
- 具有深度感的背景。

交互方式：

- 鼠标视差。
- 物体悬浮。
- 拖动旋转。
- 点击探索。
- 页面滚动驱动相机运动。

### 场景二：科研空间（Research Scene）

体现理性、科学和技术研究。

场景元素：

- 三维空间网格。
- 空域结构示意图。
- 动态节点。
- 飞行轨迹。
- 数据可视化元素。

交互方式：

### 场景三：软件展厅（Projects Scene）

### 场景四：文学空间（Writing Scene）

体现文学创作和个人精神世界。

场景元素：

- 3D 书籍。
- 悬浮书页。
- 动态文字。
- 柔和粒子。

交互方式：

- 书籍旋转。

- 点击打开作品。

## 5.3 动效设计原则

1. 动画必须有明确目的，不能单纯为了炫酷而增加。
2. 动画应当保持连续、流畅和自然。
3. 复杂动画应当尽量异步执行，不阻塞页面主要内容。
4. 3D 场景和普通 UI 应当保持统一的设计语言。
5. 不同区域可以拥有不同的空间氛围，但不能像多个完全独立的网站。
6. 不能过度使用闪烁、旋转和快速移动效果。
7. 访客必须始终能够正常滚动和访问内容。

## 5.4 字体和图形

1. 标题采用现代科技风格字体。
2. 英文标题可以适当使用大字号和字距设计。
3. 中文正文保持较高可读性。
4. 重要数字可以采用动态数字效果。
5. 技术信息可以采用等宽字体。
6. 使用 SVG、Canvas 和 3D 几何元素作为装饰图形。

# 六、技术与非功能需求（Technical & Non-Functional Requirements）

## 6.1 技术架构建议

建议采用现代前端技术构建。

可选技术：

- React / Next.js：前端框架。
- TypeScript：类型系统。
- Three.js：3D 图形渲染。
- React Three Fiber：React 环境中的 Three.js 场景管理。
- Drei：常用 3D 辅助组件。
- GSAP：复杂时间线和滚动动画。
- Framer Motion / Motion：UI 动画与交互。
- Tailwind CSS：样式开发。
- Lucide：图标系统。

技术选型应当避免不必要的重复依赖。例如，复杂的滚动驱动场景可以统一交由 GSAP 管理，普通 UI 交互使用轻量动画方案。

## 6.2 3D 渲染要求

1. 使用 WebGL 或兼容的现代 Web 图形技术实现 3D 场景。
2. 场景应支持动态相机、光照、材质、几何体和粒子系统。
3. 对模型、纹理和着色器进行合理优化。
4. 应当优先采用低面数模型和可复用几何体。
5. 避免不必要的实时阴影和高成本后处理。
6. 对粒子数量和渲染分辨率进行设备自适应。
7. 3D 组件应模块化，避免整个网站只有一个难以维护的巨大场景。
8. 离开可视区域的复杂场景应当暂停或降低更新频率。
9. 组件卸载时应正确释放 GPU 资源、纹理和几何体。
10. 3D 场景必须具有可替代的静态视觉资源。

## 6.3 性能要求

1. 网站主要内容应优先显示，不得等待 3D 场景加载完成才显示文字。
2. 首屏 3D 场景应采用异步加载。
3. 非首屏的 3D 模型和场景应按需加载。
4. 图片使用 WebP 或 AVIF 等合适格式。
5. 对不在视口中的动画进行暂停或降频。
6. 避免不必要的 DOM 更新和重复计算。
7. 目标 Core Web Vitals：
   - LCP ≤ 2.5s。
   - INP ≤ 200ms。
   - CLS ≤ 0.1。
8. 在支持 WebGL 的常见桌面设备上，目标为大部分交互场景保持约 60 FPS。
9. 移动设备以稳定流畅为目标，复杂场景可降低至适合设备的渲染质量，优先避免掉帧和过热。
10. 如果设备性能无法满足要求，必须自动切换至简化模式。

## 6.4 WebGL 降级与容错

1. 初始化 3D 场景前检测必要的图形能力。
2. WebGL 不支持时，自动显示替代背景。
3. 3D 模型加载失败时，使用图片或 CSS 元素代替。
4. 3D 渲染过程中发生上下文丢失时，尝试恢复；无法恢复时切换至静态模式。
5. GitHub API 或其他第三方接口不可用时，使用本地数据。
6. 所有错误不得导致页面主体内容无法访问。

## 6.5 响应式设计

1. 支持桌面、平板和移动设备。
2. 根据设备性能动态调整粒子数量、纹理质量及渲染分辨率。
3. 移动端简化复杂 3D 场景。
4. 移动端优先采用单列布局。
5. 交互必须支持触摸。
6. 不允许出现横向溢出。

## 6.6 SEO 要求

1. 每个页面具有独立 Title 和 Description。
2. 使用语义化 HTML。
3. 支持 Open Graph。
4. 提供 Sitemap 和 Robots.txt。
5. 支持 Person Schema。
6. 核心个人介绍和项目内容必须能被搜索引擎读取，不能全部依赖 WebGL Canvas。
7. 页面加载和 3D 渲染失败时，核心信息依旧可见。

## 6.7 可访问性

1. 支持键盘访问和导航。
2. 提供清晰的文字与背景对比。
3. 交互元素必须有可访问名称。
4. 支持 prefers-reduced-motion。
5. 3D 内容必须有对应的文本信息。
6. 不允许只有通过鼠标才能完成的重要操作。
7. 动态效果不能影响阅读和交互。

## 6.8 安全与隐私

1. 不在前端暴露私密 API Key。
2. 不暴露私人科研文件和个人隐私。
3. 对外部链接设置合理的安全属性。
4. 如果未来添加表单，必须具备输入校验与防垃圾信息机制。

## 6.9 可维护性

1. 页面模块化。
2. 3D 场景组件化。
3. UI 动画与 3D 动画尽量分层管理。
4. 内容使用结构化数据维护。
5. 不允许把所有页面和场景写在单一组件中。
6. 支持以后扩展新的研究、项目和作品。

# 九、最终产品愿景（Product Vision）

本项目不仅是一个 About Me Page，更是一个个人数字宇宙。

访客进入网站后，能够通过 3D 空间和动态交互，逐步探索网站所有者的不同身份：

- 通过 About 了解我是谁。
- 通过 Journey 了解我走过的路。

- 通过 Projects 了解我创造了什么。
- 通过 Writing 了解我写下了什么。
- 通过 Interests 了解我关注什么。
- 通过 Contact 与我建立联系。

希望最终呈现的是一个具有强烈视觉辨识度、丰富交互和内容深度的个人数字空间。

**核心表达：**

"I research the unknown, build what I imagine, write what I believe, and explore what I don't know."

探索未知，创造想象，记录思想，持续成长。
